# WRITING.md: 보고서 글쓰기 규칙

`report/` 폴더에서 보고서를 쓰거나 고칠 때 이 파일을 먼저 읽는다.

- 한국어 초안: `ko/` 폴더의 장별 파일 (`00_abstract.md` ~ `07_appendix.md`). 기준 원고이고 내용은 여기서 먼저 고친다. docx는 사용자 원고 `computervision.docx`(표지·1~2장, 사용자 서식)에 `build_docx.ps1`(→ `fill_cv_docx.py`)로 3.1 이후를 채워 `computervision_filled.docx`로 만든다. 본문 맑은 고딕 10pt, 제목 굵게 Arial 11pt, 표 9pt
- 영어 원고는 만들지 않는다(2026-11-24 결정, `report_en.md` 폐기). 장 제목만 영어로 쓴다.
- 형식은 IEEE로 통일한다(2026-11-25). 장 제목은 로마 숫자와 영어 대문자(`## III. METHOD`), 절은 `### B. Problem Setup and Data`, 소절은 `#### 1) Proportion Estimators`로 쓴다. ABSTRACT, REFERENCES, APPENDIX는 번호 없이 대문자. 본문의 참조는 `III-B절`, `IV장` 형식으로 쓴다. 절 안의 구분은 굵은 문단 머리말(**분류기.**)로 한다. 인용은 docx에서 IEEE 번호식 [n]이 된다.

규칙이 서로 부딪치면 **4절 사실 규칙**을 먼저 따른다.

## 1. 문체 (한국어)

- 평서형 문어체(-다)로 쓴다.
- 한 문단은 한 가지 주장만 다룬다. 첫 문장에 그 주장을 쓴다.
- 한 문장에는 한 가지 내용만 담는다. 길어지면 나눈다.
- 주어를 밝힌 능동 표현을 쓴다. ("측정되었다" → "우리는 측정했다" / "이 지표는 ~을 잰다")
- 꾸미는 말(매우, 획기적, 강력한)과 광고 문구는 쓰지 않는다.
- 문장 중간에 줄표(—)를 쓰지 않는다.
- 코드 이름(B1-T 같은 약칭)을 만들지 않는다. 방법은 2절 용어표의 이름으로만 부른다.

## 2. 용어표

한 개념은 한 가지 말로만 부른다. 영어는 절에서 처음 나올 때 한 번만 괄호로 적는다.

| 한국어 (고정) | 영어 (처음 나올 때 괄호) | 뜻 |
|---|---|---|
| 구성 비율 | composition proportions | 한 개체의 품종별 비율 벡터 |
| 품종 라벨 사진 | breed-labeled photos | Tsinghua Dogs 사진. "순종 사진"이라고 쓰지 않는다 |
| 특징 추출기 | feature extractor | SIFT+BoVW, CLIP, DINOv2, DINOv3. "모델"이라고만 쓰지 않는다 |
| 분류기 | classifier | 선형 품종 분류기의 확률을 비율로 읽는 방법 |
| 평균점 섞기 | prototype unmixing | 품종 평균 특징 + FCLS |
| 섞기 학습 | mixture training | 특징을 섞은 가짜 믹스로 학습 |
| 찍기 | prior baseline | 사진을 보지 않고 학습셋 품종 비율을 내는 기준 |
| 포착 혈통 비율 | captured ancestry share | 상위 3개 예측 품종의 실제 DNA 비율 합 (주 지표) |
| 커버리지 | coverage | 개체의 DNA 비율 가운데 학습 품종이 차지하는 합 |
| 상한 | upper bound | 학습 품종만 고를 수 있을 때 주 지표의 최댓값 |
| 추가 하락 | excess drop | 변형의 하락에서 대조군의 하락을 뺀 값 |
| 순종 보조 평가 | purebred auxiliary evaluation | Tsinghua val로 하는 보조 평가 |
| 믹스견 평가셋 | mixed-breed evaluation set | UF 공개 자료로 만든 평가셋 |
| 가계도형 화면 | family-tree-style view | 결과물. "족보 추정"이라고 쓰지 않는다 |

영어 용어 가운데 captured ancestry share, prototype unmixing, mixture training, excess drop은 이 보고서에서 정한 이름이다. 기존 문헌의 표준 용어인 것처럼 쓰지 않는다.

## 3. 숫자와 단위

- 지표는 0~1 비율로, 소수 셋째 자리까지 쓴다 (0.196). 퍼센트와 섞지 않는다. DNA 비율 원자료만 %로 쓴다.
- 개체 수는 "마리", 사진 수는 "장"으로 쓴다. 영어는 dogs, images.
- 반복(시드 3개, 부분 표본 3회)이 있는 결과는 대표값과 범위를 `0.255 (반복 범위 0.250–0.255)` 형식으로 쓴다. 대표값은 세 반복의 개체별 비율을 평균한 예측으로 채점한 점수다(A 최종 정의, 2026-11-24).
- 찍기와의 비교는 개체 단위 짝 차이의 평균과 ±2SE로 `+0.xxx ± 0.xxx` 형식으로 쓴다. 이 구간이 0을 포함하면 "판단 불가"로 쓴다.
- Top-1 일치는 `5/18 (0.278) [Wilson 95%: 하한, 상한]` 형식으로 쓰고, Top-1 평가 가능 비율(예: 18/20)을 함께 적는다.
- 천 단위는 쉼표를 쓴다 (61,592).

## 4. 사실 규칙 (가장 우선)

- `logs/runs.jsonl`, 결과 CSV, 채점 스크립트 출력에 없는 숫자는 쓰지 않는다.
- 확인하지 못한 내용은 지우지 말고 `[확인 필요: 무엇을]`로 남긴다.
- 서지 정보를 확인하지 못한 참고문헌은 ※를 붙인 채로 둔다. 저자, 연도, 수록처를 추측해서 채우지 않는다.
- 새 참고문헌을 넣으려면 원문 링크를 확인한 뒤에 넣는다.
- 임시 채점 숫자를 쓸 때는 같은 문장이나 표 제목에 "임시(매핑 초안 기준, 정식 채점 아님)"를 적는다. 영어는 "provisional (draft breed mapping; not the formal scoring)".
- 팀이 아직 확정하지 않은 설계는 `[TBD: 팀 확정]`으로 표시한다.

## 5. 결과 자리 표시

- 아직 없는 값은 `[TBD: 실행 이름]`으로 남긴다. 예: `[TBD: RQ1-dinov3-proto-r1..3]`
- 실행 이름이 정해지지 않았으면 `[TBD: 담당 A/B/C/D, 무엇]`으로 쓴다.
- `[TBD]`를 예상값이나 "약 ~" 같은 추측으로 바꾸지 않는다.
- 결과를 채울 때는 그 값이 나온 파일 경로(Drive 경로 제외, 저장소 기준 상대 경로나 실행 이름)를 커밋 메시지에 적는다.

## 6. 주장 수위

| 쓰는 말 | 쓸 수 있는 조건 |
|---|---|
| "높다 / 낮다" (확인적) | DINOv3에서 Holm 보정 후 유의하고, test 결과일 때 |
| "방향이 같다 / 일관" | 네 추출기 모두 차이의 부호가 같을 때 |
| "추출기 의존" | 추출기에 따라 부호가 다를 때 |
| "판단 불가" | 신뢰구간이 0을 포함하거나 표본이 작을 때 |

- dev 결과로는 결론을 쓰지 않는다. dev 숫자는 "설정 선택에 쓴 값"으로만 적는다.
- "SOTA", "최고 성능", "증명했다"는 쓰지 않는다. 해석은 "~로 읽는다(증명 아님)"로 쓴다.
- 사람 기준(MuttMix 평균 20.9%)과 우리 숫자를 같은 표나 같은 문장에서 직접 비교하지 않는다. 집계 방식이 같은지 확인하기 전까지는 배경 설명에만 쓴다.
- 특징 추출기에 순위를 매기는 문장을 쓰지 않는다. 추출기는 측정 도구다.
- DNA 검사를 대체한다는 뜻으로 읽힐 문장을 쓰지 않는다.

## 7. 표와 그림

- 번호는 IEEE 형식으로 표는 로마 숫자 `표 IV`, 그림은 아라비아 숫자 `그림 1`이다(영어 `TABLE IV`, `Fig. 1`). 부록 표는 `표 A1`. 표 제목은 위, 그림 설명은 아래에 둔다. docx에는 그림 대신 `[그림 자리: 파일명]`만 넣고 사용자가 그림을 넣는다.
- 믹스견 결과표에는 찍기와 상한 행을 항상 넣는다.
- 믹스견 결과와 순종 보조 평가 결과를 한 표에 합치지 않는다.
- 표 제목에 분할(dev/test), 개체 수, 지표의 라벨 종류(원래 비율/재정규화)를 적는다.
- 그림 파일은 `report/figures/`에 두고, 그림을 만든 코드는 `src/`의 `.py`에 둔다.

## 8. 인용

- 본문: (Zou et al., 2020) 형식. 영어도 같다.
- 참고문헌 목록: `저자 (연도). 제목. *수록처*.` 형식으로 맞춘다.
- 본문에서 인용한 문헌만 목록에 남긴다. 최종본에서 인용하지 않은 항목은 지운다.

## 9. 넣으면 안 되는 것

- 보호자 실명 등 개인정보.
- test 분할 결과를 정식 채점 전에 미리 본 숫자.
